# ReviewNatin — Full App Audit (2026-06-05)

Human-style audit driven through the running apps (mobile via Expo web at 375×812,
marketing + admin via Next.js dev), plus code-level verification. Method chosen:
**Expo Web + web properties**, fixing safe bugs inline and flagging larger items.

## TL;DR

The product is in **strong shape**. The mobile app is polished and fully functional
end-to-end — onboarding, quiz engine with bilingual (EN/TL) explanations, flashcards,
dark mode, auth gating, and a working paywall all behave correctly with **zero runtime
errors** in the console across the whole flow. The earlier "no DB questions" blocker is
resolved (1,689 published questions; quiz loads real content). The biggest real problem
is the **marketing site is not responsive** — broken on mobile, which matters because it
sells a mobile app.

## Findings

### Fixed in this audit (safe, committed)
- **F1 — `pointerEvents` prop deprecation** *(commit aeee32f)*. Moved the deprecated
  `pointerEvents` prop into `style.pointerEvents` in `study.tsx` footer and
  `offline-banner.tsx`. Behavior identical; silences a repeated RN deprecation on native + web.

### High priority (flagged — needs decision/larger work)
- **H1 — Marketing site is not responsive.** `apps/marketing/app/page.tsx` is built
  entirely with fixed inline styles and **no media queries / no hamburger menu**. On mobile
  (375px): the desktop nav overflows off-screen and the hero phone mockup overlaps and
  covers the headline + subtext. High impact — this is the landing page for a *mobile* app.
  Fix = responsive rework (breakpoints, mobile nav, stacked hero). Not a safe inline fix.

### Medium priority (flagged)
- **M1 — Marketing overpromises the exam catalog.** The hero/body heavily promote
  **UPCAT, PSHS-NCE, PRC Board, Bar, Scholarships** and "every Filipino exam," but the app
  only ships **CSE (Pro/Sub), PNLE, LET (Elem/Sec)**. The paywall says "All Phase 1 exams,"
  so these may be intentionally forward-looking — but as written it reads as available now.
  Decision: scope the copy to current exams, or clearly label future ones "coming soon."
- **M2 — "142k+ Filipinos reviewing" on a beta.** Appears in the marketing badge and the
  onboarding "X reviewers" counts. If not real, it conflicts with the app's own
  "no fake progress here" ethos and is a trust/▲ App Store review risk. Verify or soften.

### Low priority / polish (flagged)
- **L1 — `shadow*` style deprecation (web only).** RN-web warns to use `boxShadow`. On
  native iOS/Android `shadow*` is still the correct API — **do not "fix"** unless/until you
  formally support web; it would break native shadows.
- **L2 — Expo `web` platform declared but non-functional.** `app.json` lists `web`, but
  `react-native-web`/`react-dom`/`@expo/metro-runtime` aren't installed. Either add them and
  support a web build, or remove `web` from the platforms to avoid a broken target.
  (They were installed transiently for this audit, then reverted — repo is clean.)
- **L3 — Quiz timer keeps counting during answer review**, inflating per-question time.
  Consider pausing on "Check answer."
- **L4 — No confirmation when abandoning a quiz** (the ✕ exits immediately). Fine for
  practice; consider a confirm for mock exams.
- **L5 — Greeting reads "Good evening, / Hey, Reviewer!"** (two greetings). Stylistic;
  optional copy tightening.
- **L6 — `cse-subprofessional → clerical → spelling` topic has 0 questions** (content gap
  noted previously). A user choosing it hits an empty quiz.

## Feature recommendations
1. **Marketing: responsive rebuild** (covers H1) — highest ROI; it's the conversion surface.
2. **Empty-state guards** — when a topic/subject has 0 published questions, show a friendly
   "content coming soon" instead of an empty quiz (covers L6 and similar).
3. **Mock-exam abandon confirm + autosave** (covers L4) so long timed exams aren't lost.
4. **Exam catalog "coming soon" badges** to honestly preview UPCAT/PRC/etc. (covers M1).
5. **Optional Expo web build** — the app already renders cleanly on web; a public web
   version could be a low-cost acquisition channel (covers L2) if native modules are shimmed.

## Notes on method / limits
- Mobile audited via Expo web (renders the same RN tree). Native-only behaviors —
  push notifications, in-app purchases (StoreKit/Play Billing), deep links, haptics — can't
  execute on web and were reviewed at the code level only; verify on device/simulator.
- Admin authenticated UI not exercised (no staff credentials).
