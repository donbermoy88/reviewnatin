# Android-First / Google Play Readiness Audit
**Date:** 2026-06-16
**Goal:** Run/test/debug on Android, then prepare Google Play closed testing.
**App identity (unchanged):** `ph.reviewnatin.app` · ReviewNatin · v1.0.0 (versionCode 1)

## TL;DR
The project is an Expo SDK 56 (RN 0.85.3) app using Continuous Native Generation.
Android was already configured in `app.config.js`/`app.json`. The app now **builds,
installs, launches, and runs end-to-end on an Android emulator** (Pixel/API 35).
One launch-blocking native crash was found and fixed, and the Android hardware
back button was wired up. iOS setup was not touched.

## Bugs found & fixed
1. **Launch crash — AdMob `Invalid application ID` (FIXED + HARDENED).**
   `react-native-google-mobile-ads` is a linked native dep; its
   `MobileAdsInitProvider` aborts the process at startup without a
   `com.google.android.gms.ads.APPLICATION_ID` manifest meta-data, which the
   AdMob config plugin previously injected only when `EXPO_PUBLIC_ADMOB_*_APP_ID`
   was set. Fix: `app.config.js` now **always** injects the plugin — non-production
   builds fall back to Google's official **public test** App IDs (so no build can
   crash on launch), and **production requires the real App IDs or the build
   throws** (verified: prod config throws without them; prevents shipping test ads).
   Ad *unit* IDs stay unset → ads disabled. No `.env` entry is needed anymore.
2. **Android hardware back exited the app mid-onboarding (FIXED).**
   Onboarding is one route with internal step state; the OS back button wasn't
   intercepted, so back at step 1 exited to the launcher. Added a `BackHandler`
   in `app/onboarding/index.tsx` that steps backward (exits only at step 0).
   No-op on iOS.

## Non-issues (verified, no action needed)
- **`SYSTEM_ALERT_WINDOW` permission** in the manifest comes from `expo-dev-client`
  + RN's debug manifest. It is present only in dev/`development` builds; a
  `production` prebuild drops `expo-dev-client`, so it will **not** ship in the AAB.
- **`READ/WRITE_EXTERNAL_STORAGE`** are capped at `maxSdkVersion=32` — compliant.
- SDK levels resolve to **compileSdk 36 / targetSdk 36 / minSdk 24** — meets
  Play's current target-API requirement (≥35).

### You must provide / do ⚠️
- [ ] **Release keystore** — let EAS generate/manage it (recommended) via
      `eas build --profile production --platform android`, OR generate your own
      and configure local signing. *(Do not commit the keystore.)*
- [ ] **Real AdMob Android App ID** (replace the test value in `.env` / EAS env) —

      SHA-1 (from `eas credentials`) in Google Cloud and set
      `EXPO_PUBLIC_GOOGLE_ANDROID_CLIENT_ID`; run `npm run supabase:android`.

- [ ] **Production prebuild env**: `EXPO_PUBLIC_SENTRY_DSN` is **required** (build throws
      otherwise) and both AdMob app IDs. Set them in the EAS `production` profile `env`.
- [ ] **Data Safety form** — declare: account (email, name via Google), app activity
      (quiz/analytics), and advertising ID (AdMob). Plus data deletion = yes.
- [ ] **Content rating** questionnaire — educational; expected "Everyone".
- [ ] **Target audience** — not directed at children (board-exam reviewers / adults).
- [ ] **App access instructions** for reviewers — note guest mode; optionally supply a
      test login (e.g. a seeded reviewer@ account) since premium gating exists.
- [ ] **Store listing assets**: short + full description, **feature graphic 1024×500
      (not present — must create)**, **≥2 phone screenshots (must create)**, 512² icon

## Exact next steps to reach Play closed testing
```bash
# 0) Set production env in the EAS "production" profile (eas.json env or EAS secrets):
#    EXPO_PUBLIC_SENTRY_DSN, EXPO_PUBLIC_ADMOB_ANDROID_APP_ID (real),
#    EXPO_PUBLIC_ADMOB_IOS_APP_ID (real), EXPO_PUBLIC_GOOGLE_ANDROID_CLIENT_ID

cd apps/mobile

# 1) Build a release AAB in the cloud (EAS generates + manages the keystore):
eas build --profile production --platform android        # outputs a signed .aab

# 2) Create the app in Google Play Console, then submit to the internal track:
#    (needs the Google Play service account JSON configured in EAS)
eas submit --profile production --platform android

# 3) In Play Console: complete Data Safety, Content rating, Target audience,
#    Store listing (descriptions + feature graphic + screenshots), and add testers
#    to the closed/internal testing track.

# 4) Register SHA-1 for Google Sign-In + create Play Billing products to match
#    ANDROID_PRODUCT_SKUS, then verify IAP/Google sign-in on an internal-track install.
```

## Local Android run commands used (for reference)
```bash
export ANDROID_HOME=$HOME/Library/Android/sdk
$ANDROID_HOME/emulator/emulator -avd Medium_Phone_API_35 &
cd apps/mobile
npx expo prebuild --platform android          # generates android/ from app config
cd android && ./gradlew :app:assembleDebug    # build debug APK
adb install -r app/build/outputs/apk/debug/app-debug.apk
npx expo start --dev-client                   # Metro
adb shell am start -a android.intent.action.VIEW \
  -d "reviewnatin://expo-development-client/?url=http%3A%2F%2Flocalhost%3A8081"
# (or simply: npx expo run:android  — does build+install+Metro in one step)
```
