# Android-first release guide (Google Play)

This is the Android counterpart to `BUILDING.md`. The goal is **Android-first
publishing to Google Play** (closed testing → production) **without breaking the
existing iOS setup**. iOS support is preserved as-is; nothing here removes it.

> The app uses **Expo Continuous Native Generation** — there is no committed
> `android/` folder. The source of truth is `app.json` + `app.config.js`, and the
> native project is generated by `expo prebuild` / EAS at build time.

## 2. Running on Android (do this on the MacBook)

This cloud session has Java + Gradle but **no Android SDK, no `adb`, and no access
to your connected phone**, so the emulator/device run and the `.aab` build must be
done on your Mac. Commands below are exact.

### One-time toolchain setup (macOS)

```bash
# Android Studio (includes SDK + emulator)
brew install --cask android-studio
# Open Android Studio once → More Actions → SDK Manager → install:
#   - Android SDK Platform 36, Build-Tools 36, Platform-Tools, Emulator
# Then add to ~/.zshrc:
export ANDROID_HOME="$HOME/Library/Android/sdk"
export PATH="$PATH:$ANDROID_HOME/platform-tools:$ANDROID_HOME/emulator:$ANDROID_HOME/cmdline-tools/latest/bin"
# reload: source ~/.zshrc ; verify:
adb --version && emulator -version
```

### Option A — real device over ADB Wireless (your setup)

```bash
# Phone: Settings → Developer options → enable "Wireless debugging".
# First pairing (use "Pair device with pairing code" on the phone):
adb pair <PHONE_IP>:<PAIR_PORT>        # enter the 6-digit code shown on phone
adb connect <PHONE_IP>:<CONNECT_PORT>  # the port under "Wireless debugging"
adb devices                            # should list the phone as "device"

# From repo root: build + install the dev client, then start Metro.
# react-native-iap / AdMob / Sentry are native, so a plain Expo Go won't work —
# you need a dev client (run:android builds and installs one):
npm run android --workspace=apps/mobile          # = expo run:android (first build ~10-15 min)

# Subsequent JS-only runs (helper handles adb reverse / tunnel automatically):
npm run android:dev --workspace=apps/mobile      # USB/wireless device → localhost Metro
```

`scripts/start-android-device.mjs` (used by `android:dev`) auto-detects the
connected device, sets up `adb reverse` for Metro, and falls back to an Expo
tunnel if no device is found.

### Option B — emulator

```bash
# Create an AVD once (API 36, Pixel 7):
sdkmanager "system-images;android-36;google_apis;arm64-v8a"   # x86_64 on Intel Macs
avdmanager create avd -n Pixel7_API36 -k "system-images;android-36;google_apis;arm64-v8a" -d pixel_7
emulator -avd Pixel7_API36 &
adb devices                                       # wait until "device"
npm run android --workspace=apps/mobile
```

**Note on native features in dev:** in-app purchases, restore, remote push, and
real ads are intentionally disabled in dev/non-store builds
(`lib/iap/availability.ts`, `lib/device-capabilities.ts`). To exercise Google Play
Billing you must test an **internal/closed-testing AAB** signed by Play, not a dev
client.

## 3. Building for Google Play

```bash
# Closed/internal testing (installable APK for quick sideload tests):
npm run eas:build:android:preview --workspace=apps/mobile

# Production AAB for Play upload (app-bundle, autoIncrement versionCode):
npm run eas:build:android:prod --workspace=apps/mobile

# Submit to the Play "internal" track (after Play Console + service account set up):
eas submit --profile production --platform android
```

EAS generates and stores the **upload keystore** in the cloud (`eas credentials -p
android` to inspect/export the SHA-1 you'll need for the Google Sign-In Android
OAuth client and Play App Signing).

## 4. Google Play closed-testing readiness checklist

Legend: ✅ ready in repo · 🟡 you must provide · ⬜ Play Console action

### Build & signing
- ✅ AAB build profile (`eas.json` → `production.android.buildType: app-bundle`)
- 🟡 Upload keystore — let **EAS manage** it (recommended) or supply your own `.jks`
- ⬜ Enroll in **Play App Signing** (Play Console manages the release key)

### Store listing (Play Console → Main store listing)
- 🟡 App icon (512×512 PNG) — derive from `assets/icon.png`
- 🟡 Feature graphic (1024×500 PNG)
- 🟡 Phone screenshots (min 2; 16:9 or 9:16, e.g. 1080×1920) — capture from device/emulator
- 🟡 Short description (≤80 chars)
- 🟡 Full description (≤4000 chars)
- ✅ Contact email — your developer email
- ✅ Privacy Policy URL — `https://reviewnatinph.com/privacy` (live on marketing site)
- ✅ Terms URL — `https://reviewnatinph.com/terms` (referenced in-app; add to listing if prompted)

### App content (Play Console → Policy → App content)
- ⬜ **Data Safety form** — declare: account (email), purchases, app activity/analytics,
      and advertising ID (AdMob). Mark data encrypted in transit; provide deletion method
      (in-app "Delete account" already implemented — `lib/auth/delete-account.ts`).
- ⬜ **Content rating** questionnaire (educational app → likely Everyone)
- ⬜ **Target audience & content** (select age groups; the app is for adult exam-takers)
- ⬜ **Ads declaration** — "Yes, contains ads" (AdMob)
- ⬜ **App access** — provide reviewer **test login** (see below); the app also allows
      guest use, so note "Sign-in optional; demo account provided for premium areas."
- ⬜ Government/financial/health declarations — N/A

### Reviewer access
- 🟡 **Test account**: create a Supabase user (email+password) with an active demo
      entitlement so reviewers can see premium screens. Enable demo IAP/entitlements
      with `npm run db:enable-demo-iap` and document the credentials in "App access".

### Google Play Billing (premium features / subscriptions)
- ✅ Client billing flow (`react-native-iap`, `requestPurchase` with `google.skus`)
- ✅ Server-side purchase verification (`iap-verify` → androidpublisher v3)
- ⬜ Create the **products/subscriptions in Play Console** using the exact Android
      product IDs in `lib/iap/product-skus.ts`:
      `plus_monthly`, `plus_six_months`, `plus_yearly`,
      `exam_pass_cse_pro`, `exam_pass_cse_sub`, `exam_pass_let_elem`,
      `exam_pass_let_sec`, `exam_pass_pnle`
- 🟡 **`GOOGLE_PLAY_SERVICE_ACCOUNT_JSON`** secret for the `iap-verify` Supabase
      function — create a service account in Google Cloud, grant it access in Play
      Console (Users & permissions → API access), and set it as a Supabase secret.
      Also confirm `ANDROID_PACKAGE=ph.reviewnatin.app` is set for that function.
- ⬜ (Optional) **Real-time developer notifications** Pub/Sub topic for the
      `store-webhook` function, to handle renewals/cancellations.

### Auth
- 🟡 **Android OAuth client** in Google Cloud (package `ph.reviewnatin.app` + the
      build's SHA-1). Use debug keystore SHA-1 for local dev and the **Play App
      Signing SHA-1** for store builds. Helper: `scripts/configure-android-oauth.mjs`,
      then `npm run supabase:google`. Put the client ID in
      `EXPO_PUBLIC_GOOGLE_ANDROID_CLIENT_ID`.

### Crash reporting / config (enforced at prebuild for `production`)
- 🟡 `EXPO_PUBLIC_SENTRY_DSN` (build **throws** without it on production)
- 🟡 `EXPO_PUBLIC_ADMOB_ANDROID_APP_ID` **and** `EXPO_PUBLIC_ADMOB_IOS_APP_ID`
      (set both or neither — a missing `GADApplicationIdentifier` crashes the ads SDK)

## 6. Exact next steps to reach closed testing

1. On the Mac: install Android Studio + SDK 36, connect the phone via ADB Wireless,
   run `npm run android --workspace=apps/mobile` → confirm the app launches.
2. Create the Play Console app (`ph.reviewnatin.app`), enroll in Play App Signing.
3. Set production env (Sentry, AdMob, Google service account) per §5.
4. `npm run eas:build:android:prod --workspace=apps/mobile` → produces the `.aab`.
5. Create Play Console products/subscriptions with the IDs in §4.
6. Complete Data Safety, content rating, target audience, ads, and app-access forms.
7. Upload the `.aab` to the **Internal testing** (or Closed testing) track, add testers,
   and roll out.
8. Verify Google Play Billing + Google Sign-In on a tester device using the Play-signed
   build (these are disabled in dev builds by design).
